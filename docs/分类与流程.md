# 动效镜头的分类与入库

同一条动效可以适配多个题材。用途是主分类，内容主题与表现手法分别作为标签，避免把同一镜头复制到多个文件夹。

| 用途 | 收什么 | 个人口播 / AI 用法 |
| --- | --- | --- |
| 开场与身份 | 姓名、人物、片头、标识 | 人物介绍、栏目开场 |
| 文字与观点 | 金句、强调、对比 | 儒释道观点、成长思考、AI结论 |
| 信息展示 | 卡片、图表、步骤、屏幕 | 经历、观点清单、AI工具操作 |
| 转场与衔接 | 遮罩、匹配、推拉切换 | 话题转换、章节衔接 |
| 镜头与氛围 | 光影、粒子、情绪镜头 | 思考留白、科技氛围 |
| 收尾与引导 | 总结、结束、关注提示 | 收束观点、下集提示 |

主题分为 AI工具、AI趋势、AI教程、AI创作，以及自我介绍、儒家、佛学、道家、个人成长、思考表达、生活记录、工作分享。还记录横竖屏、时长、引擎和风格标签。主题表达的是“适合用于”，不表示镜头里已经出现相应内容。空主题暂不填充示例作品。

## 参考依据

- [Motion Array](https://motionarray.com/motion-graphics-templates/) 按标题、片头、信息图、转场等用途筛选，并单独区分横竖屏。这里取其用途与画幅分离的结构。
- [Envato](https://elements.envato.com/video-templates/) 按开场、标题、信息图、产品宣传等用途组织模板；复用入口需要同时提供成片和可改工程。
- [Eagle](https://en.eagle.cool/support/desktop/organize) 同时使用文件夹、标签和重复文件识别。这里只存一份镜头，用多个主题找到它。
- [PySceneDetect](https://github.com/Breakthrough/PySceneDetect) 可识别镜头切点；切点检测不能代替动效图层、节奏与缓动分析。当前工具直接用已有 FFmpeg 提取切点候选和关键帧，没有另装该 Python 包。
- [Remotion 官方模板](https://www.remotion.dev/templates)、[HyperFrames 官方实例](https://github.com/heygen-com/hyperframes/blob/main/docs/examples.mdx)、[Motion Canvas](https://github.com/motion-canvas/motion-canvas) 可供学习组织与实现方法。目前继续使用现有 Remotion / HyperFrames，不新增第三套制作引擎。

## 对话驱动的流程

1. 发视频或链接给 Codex：完整原片本地保留；计算 SHA-256，重复文件复用原编号。每条动效使用 M001、M002 等稳定编号，完整版视频继续使用 V001 等编号。
2. 提取媒体信息、镜头切点候选和关键帧，写清观察到的动作、图层、节奏与建议参数。原片无法证明的缓动或原软件不当成事实。
3. 使用现有引擎复刻，按可替换照片、文字、颜色、时长的方式保存配置。新版本单独保存；完成解码与画面验证后才登记为完成。
4. 整理 MP4、封面、公开拆解、源包；按用途＋主题＋画幅登记。源包只包含可复用工程和必要素材。
5. 自动同步至 Eagle 的“动效素材”，将已验证个人成片实际采用的最终版动效发布至本仓库，验证公网预览和下载。参考录屏、工作日志和本机路径继续保留在本地。

未来新视频在对话里触发制作流程；成片交付时会自动发布实际采用的最终动效，Codex每小时检查最终版发布队列补漏。只有当前成片采用记录、文件哈希与解码验证通过的独立最终动效进入自动发布，未采用候选继续留本地。该检查依赖本机、网络与Codex运行状态。网页的“导入我的素材”仍只保存到当前浏览器；由 Codex 完成的动效才经过上述工程入库与 GitHub 发布步骤。

## 维护入口

- `assets/library.json`：公开目录唯一编辑源。
- `assets/taxonomy.json`：用途与主题词表。
- `scripts/build-catalog.mjs`：同步静态卡片、页面内嵌目录与词表。
- `scripts/check.mjs`：检查素材、分类、链接、重复 ID 和公开文件隐私。
- 每条公开动效同时提供 MP4、拆解与源包；旧版独立保留，不覆盖原参考。
